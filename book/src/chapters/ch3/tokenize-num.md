# Строко-числа

## Введение

Перед тем как токенизировать числа, для начала выявим правила токенизации. В Pebble числа токенизируются
по следующим правилам:

1. Числа содержат цифры из десятичной системы счисления (`123`).
2. Числа могут иметь не более одной точки (`123.45`, `123`).
3. Дробные числа вида `0.x` (*где `x` --- набор цифр десятичной системы счисления*) можно писать как `.x`
(`.5` эквивалентен записи `0.5`).
4. В конце числа может идти суфикс (`i8`/`i16`/`i32`/`i64` для целочисленных знаковых типов,
`u8`/`u16`/`u32`/`u64` для целочисленных беззнаковых типов, `f32`/`f64` для дробных типов).
5. Целые и дробные числа без суффикса могут приводиться к ожидаемому типу. Если никакой тип не ожидается, то
приводится к `int32`:

```pebble
var x        = 10; // 10 выведется как тип int32
var y: uint8 = 10; // 10 выведется как тип uint8

var w          = 123.45; // 123.45 выведется как тип float64
var z: float32 = 123.45; // 123.45 выведется как тип float32
```

## Новые токены

Литералы с суфиксами помогают определить желаемый тип числа. Но на этапе лексинга суффиксы вообще не имеют
значения --- самое главное записать их в токен, а дальнейшие действия с числами и этими суффиксами будет
сильно позже.

Теперь исходя из этой информации дополним `TokenKind`:

```cpp
// include/pebble/lexer/token_kind.h

$#pragma once
$#include <cstdint>
$
$namespace pebble {
$
enum class TokenKind : std::uint8_t {
    Id, // Идентификатор

    NumLit,   // Числовой литерал
    // ...
};
$
$}
```

## Токенизация

Объявим метод `tokenizeNumLit`, который и будет заниматься токенизацией числовых литералов.

```cpp
// include/pebble/lexer/lexer.h

$#pragma once
$#include "pebble/diagnostic/engine.h"
$#include "pebble/lexer/token.h"
$
$namespace pebble {
$
class Lexer {
private:
    Token
    tokenizeNumLit ();

    void
    skipComment ();
    // ...
};
$
$}
```

В `NextToken` нужно определить, является ли текущий символ (`peek (0)`) началом числового литерала.
Исходя из спецификации Pebble числа могут начинаться либо с десятичной цифры (`123`), либо с точки (`.5`).
Но точка --- это тоже токен (о ней и других служебных символах в разделе
[3.8. Операторы](./operators.md)). Чтобы лексер понял, что `.` --- это именно начало числового литерала,
нужно сделать уточнение --- после точки обязательно должна идти десятичная цифра, иначе лексер подумает,
что `.` --- это дробное число, просто вообще без цифр.

```cpp
// src/lib/lexer/lexer.cpp

Token
Lexer::NextToken () {
    // ...
        // Десятичная цифра
    if (std::isdigit (static_cast<unsigned char> (peek ())) != 0
        // Или точка, после которой идет десятичная цифра
        || peek () == '.' && std::isdigit (static_cast<unsigned char> (peek (1))) != 0) {
        return tokenizeNumLit ();
    }
}
```

Теперь попробуем реализовать метод `tokenizeNumLit`. Лексер просто "съедает" все символы десятичных цифр
или точек. Если `tokenizeNumLit` уже встречал точку, то следующая точка не будет являться частью числового
литерала (правило 2). Например, текст `123.4` воспринимается лексером как один токен
`Token (NumLit, "123.4", Pos (...))`. Но вот текст `123.4.5` будет восприниматься лексером как два
токена: `Token (NumLit, "123.4", Pos (...))` и `Token (NumLit, ".5", Pos (...))`, потому что лексер,
увидев вторую точку, остановит анализ числа, потому что до этого уже встречал точку в части `123.4`.
Если вызывать `NextToken` после того, как лексер вернул токен `123.4`, он начнет токенизацию со второй
точки и это спровоцирует его (по правилу 3) сгенерировать ещё один токен числа: `.5`. И это
должно быть правильным поведением лексера.

Когда `tokenizeNumLit` закончит съедать символы числа, он обязан проверить символы после него (суффиксы).
Сами суффиксы **сохраняются в `Val` токена**. Например, число `123.45f32` превратиться в токен
`Token (NumLit, "123.45f32", Pos (...))`. Не забываем, что `Val` --- точное отражение токена
в строке. Пусть пропуском суффикса занимается метод `skipNumSuffix`.

```cpp
// include/pebble/lexer/lexer.h

$#pragma once
$#include "pebble/diagnostic/engine.h"
$#include "pebble/lexer/token.h"
$
$namespace pebble {
$
class Lexer {
private:
    Token
    tokenizeNumLit ();

    void
    skipNumSuffix ();
    // ...
};
$
$}
```

Важно понимать, что для лексера суффикс числа --- это **любая последовательность букв и цифр сразу после
числа без пробелов**. Текст `123abc` превратится в токен `Token (NumLit, "123abc", Pos (...))`.
Это называется **Maximal Munch**, или же **максимальное поглощение**. Лексер просто жадно поедает все
символы, которые могут находится в конкретном токене, а уже валидировать их будет не лексер, а кто-то другой.
Да, `abc` --- это невалидный суффикс. Но определит его валидность уже не лексер. Задача лексера --- просто
слайсить текст на токены. Такое тяжело принять, но это правильная архитектура.

```cpp
// src/lib/lexer/lexer.cpp

// ...

Token
Lexer::tokenizeNumLit () {
    auto start = _pos;
    bool hasDot{};
    while (!isAtEnd() && (std::isdigit (static_cast<unsigned char> (peek ())) != 0
        || peek () == '.')) {
        if (peek () == '.') {
            if (!hasDot) {
                hasDot = true;
            } else {
                break;
            }
        }
        advance ();
    }
    skipNumSuffix ();
    return tok (
        TokenKind::NumLit,
        std::string_view (&_source[start], _pos - start),
        span (start, _pos));
}

void
Lexer::skipNumSuffix () {
    while (!isAtEnd () && std::isalnum (static_cast<unsigned char> (peek ())) != 0) {
        advance ();
    }
}

// ...
```

Флаг `hasDot` нужен, чтобы `tokenizeNumLit` запомнил, встречал ли он уже точку. Если встречал, то токенизация
числа останавливается (правило 2). В противном случае флаг `hasDot` взводится в значение `true`
(`tokenizeNumLit` впервые встретил точку). После токенизации числа нужно пропустить его суффикс. Лексеру
всё равно на него, самое главное --- вызывать `advance ()` для всех символов, которые потенциально похожи
на суффикс: буквы и десятичные цифры.
