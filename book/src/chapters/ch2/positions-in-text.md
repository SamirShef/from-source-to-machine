# Координаты в тексте

## Введение

Вспомним первый из трёх вопросов, на который должен ответить компилятор при ошибке: **«Где ошибка?»**.

Чтобы дать точный ответ, нам нужно ввести понятие **позиции в исходном коде**. Любой элемент
программы --- будь то токен, ключевое слово, вызов функции или вся конструкция цикла --- занимает
определённое место в файле.

## Точки позиционирования

Человеку удобно читать позиции в формате `файл:строка:столбец`. Для представления строки и столбца создадим
простую структуру `Loc` (от *Location*):

```cpp
// include/pebble/basic/loc.h

#pragma once
#include <cstdint>

namespace pebble::basic {

struct Loc {
    std::uint32_t Line; // Начинается с 1
    std::uint32_t Col;  // Начинается с 1

    Loc (std::uint32_t line, std::uint32_t col) : Line (line), Col (col) {}
};

}
```

Однако хранить строки и столбцы для каждого токена и узла AST --- крайне неэффективно. При любом изменении
файла (или при подсчёте символов новой строки) нам пришлось бы постоянно пересчитывать эти значения.
Более того, компилятор должен знать, к какому именно файлу относится позиция.

Поэтому для внутренней работы компилятора мы введём более лёгкую структуру --- `Pos` (от *Position*):

```cpp
// include/pebble/basic/pos.h

#pragma once
#include <compare>
#include <cstdint>

namespace pebble::basic {

struct Pos {
    std::uint32_t Start; // Байтовое смещение от начала файла
    std::uint32_t FileId;

    Pos (std::uint32_t start, std::uint32_t fileId) : Start (start), FileId (fileId) {}

    auto operator<=> (const Pos &) const = default;
};

}
```

> **Обратите внимание:** `Start` хранит именно *байтовое смещение* от начала файла (начинающееся с 0), а
не количество символов. В мире UTF-8 один символ может занимать несколько байт, поэтому работать с
абсолютными байтовыми индексами в памяти намного быстрее и надёжнее.

Мы не храним путь к файлу или его содержимое прямо в `Pos`. Вместо этого за хранение файлов будет отвечать
специальный компонент --- **Менеджер ресурсов** (SourceManager). Он выдаёт каждому открытому файлу
уникальный числовой `FileId`.

Благодаря этому `Pos` занимает всего 8 байт (два `std::uint32_t`), и его крайне дёшево передавать по значению.
Именно `Pos` мы будем использовать во всём компиляторе, а «человекочитаемую» структуру `Loc` будем вычислять
«на лету» (lazily) --- только тогда, когда потребуется сформировать диагностическое сообщение.

## От точек к отрезкам: `Span`

`Pos` и `Loc` задают одиночную точку в коде. Но ошибки редко происходят в «точке» --- обычно они затрагивают
целые выражения, идентификаторы или диапазон символов. Отрезок, который подчёркивает компилятор в консоли,
называется **`Span`** (или диапазоном):

```cpp
// include/pebble/diagnostic/span.h

#pragma once
#include "pebble/basic/pos.h"

namespace pebble::diagnostic {

struct Span {
    basic::Pos Start;
    basic::Pos End;

    Span (basic::Pos start, basic::Pos end) : Start (start), End (end) {}

    auto operator<=> (const Span &) const = default;
};

}
```

Диапазон `Span` представляет собой полуинтервал `[Start, End)`, где `Start` указывает на первый байт
конструкции, а `End` — на первый байт *за* ней.

Теперь у нас есть полный набор структур для точного позиционирования любого фрагмента кода!
